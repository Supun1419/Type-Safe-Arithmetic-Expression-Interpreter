Design summary

The project models expressions with the algebraic data type Expr. Its alternatives are numeric literals, variables, the four arithmetic operators, and a local Let binding. An environment is a list of name/value pairs. Placing a new pair at the front implements lexical shadowing without changing an existing environment.

Safety: eval :: Env -> Expr -> Either String Double returns either a useful error message or a number. Division by zero and undefined variables therefore remain ordinary, typed results instead of terminating the program.

How to run

Put Expr.hs and Main.hs in the same directory. With GHC installed, execute:

runghc Main.hs

# or compile with warnings enabled
ghc -Wall Main.hs -o expression-interpreter
./expression-interpreter

Part D — Comparative Analysis

Equivalent imperative evaluator (Java-like pseudocode)

double eval(Map<String, Double> env, Node expr) {
    switch (expr.kind) {
        case LIT: return expr.value;
        case VAR:
            if (!env.containsKey(expr.name))
                throw new Error("undefined variable: " + expr.name);
            return env.get(expr.name);
        case ADD: return eval(env, expr.left) + eval(env, expr.right);
        case SUB: return eval(env, expr.left) - eval(env, expr.right);
        case MUL: return eval(env, expr.left) * eval(env, expr.right);
        case DIV:
            double denominator = eval(env, expr.right);
            if (denominator == 0) throw new Error("division by zero");
            return eval(env, expr.left) / denominator;
        default: throw new Error("unknown expression tag");
    }
}

Comparison

Error representation and propagation. The Haskell signature announces that evaluation can fail: callers must handle both Left String and Right Double. The do expressions automatically stop at the first Left and pass that error outward. The Python version throws exceptions, which are invisible in its function signature; a caller can forget to catch them. It must also reject unknown tags at runtime.

State and control flow. Haskell follows the tree through recursive pattern matching. Each call returns a new value, and extending an environment creates a new list whose tail is the previous environment. The imperative version uses a switch and a mutable local variable for the denominator. Its control flow and manually tagged Node representation require runtime checks.

Compile-time guarantees. Haskell checks that every successful branch returns a Double, every failure is a String, and the caller cannot accidentally use an Either String Double as a number. With warnings enabled, GHC also reports incomplete pattern matches when a new Expr constructor is not handled. The Python encoding permits malformed tuples, misspelled tags, missing fields, and nonnumeric payloads until the affected line executes.

Trade-off. The imperative representation may look familiar and makes control flow explicit. Haskell more closely matches the expression grammar, while its types move several defect categories from runtime to compile time.


Part E — Reflection

Pure functions

A pure function produces the same result whenever it receives the same inputs and has no observable side effects. Both eval and simplify are pure. For example, evaluating Div (Lit 8) (Lit 0) in the same environment always returns Left "division by zero"; it does not print, throw an exception, read a global variable, or modify the environment. This makes individual cases easy to reason about and test as input/output equations.

simplify is also pure even though it transforms a tree. It recursively constructs a new expression. Rules such as x + 0 -> x, x * 1 -> x, x * 0 -> 0, x - 0 -> x, and x / 1 -> x do not alter the original value. Constant subexpressions are folded, except division by zero, which is preserved so that eval can still report the error.

Immutability and scope

Values are immutable: once an Expr or environment list has been created, evaluation cannot update it in place. For Let "x" bound body, the bound expression is evaluated first and the body receives ("x", value) : env. The old environment remains available unchanged, while lookup selects the first matching pair. This gives predictable local shadowing without mutable variables.

Why the shape of Expr matters

Expr is a sum type: a value is exactly one constructor at a time. Each constructor carries only the data it requires. Lit always contains a Double; Var always contains a name; binary operators always contain two complete expressions; and Let always contains a name, a bound expression, and a body. Consequently, states such as an addition with one missing operand or a literal containing text cannot be constructed through the type.

Pattern matching then exposes those shapes safely. The evaluator handles all seven constructors, and a compiler warning highlights omissions after the type is extended. Not every semantic error can be removed by the data type: whether a variable exists depends on the supplied environment, and a denominator can evaluate to zero. Those cases are represented explicitly by Either, keeping failure inside the function's type.

Higher-order functions and currying

evalBatch uses map (eval env). Currying fixes the shared environment first, producing a function Expr -> Either String Double that map applies to each item. A foldr retains successful values, while batchSummary folds the same outcomes into success and failure counts. These functions separate traversal from the operation applied to each element.
